NOVA ALWAYS-LISTENING / BACKGROUND VOICE UPDATE

What changed:
1. Added NovaBootReceiver to restore hands-free mode after device reboot when the user had explicitly enabled it.
2. Added RECEIVE_BOOT_COMPLETED permission and BOOT_COMPLETED receiver declaration.
3. Hands-free preference is now persisted in SharedPreferences, so reopening NOVA remembers the user's choice.
4. NovaVoiceService now guards its restart scheduler so multiple SpeechRecognizer sessions are not queued at the same time.
5. Voice service destroys the previous recognizer before scheduling the next session after results/errors, reducing stale recognizers and duplicate microphone sessions.
6. MainActivity reports when Android blocks background microphone startup instead of silently pretending it worked.
7. The existing foreground microphone service remains the actual always-listening engine.

Important Android limitation:
- This is best-effort background listening, not a hardware-level Google Assistant/Siri hotword engine.
- The user must grant microphone permission and enable hands-free at least once.
- Android may block a microphone foreground service from being started automatically at boot on some OS/device versions. The receiver catches that restriction safely.
- If the user force-stops NOVA from Android Settings, Android can prevent automatic restart until the user launches it again.
- Continuous SpeechRecognizer listening consumes more battery than a dedicated low-power hotword DSP/model.
- No API key is embedded in these changes.

Testing required on the target tablet:
A. Launch NOVA and grant microphone + notification permissions.
B. Tap START HANDS-FREE • HEY NOVA once.
C. Lock the tablet and say: "Hey NOVA".
D. Close the NOVA UI and repeat.
E. Reboot the tablet and test again. If Android blocks microphone FGS-at-boot, open NOVA once and start hands-free again.
F. Check battery usage after 30-60 minutes.
